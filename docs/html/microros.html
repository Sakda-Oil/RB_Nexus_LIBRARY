micro-ROS บน ESP32

RB_Nexus 0.2.1 · ESP32-WROOM-32 · Arduino-ESP32 3.3.10

ใช้ไลบรารีจริง

รุ่นนี้ยกเลิก fallback stubs หากไม่มี micro_ros_arduino จะคอมไพล์ตัวอย่าง ROS ไม่ผ่าน ซึ่งช่วยป้องกันโปรแกรมที่ดูเหมือนทำงานแต่ไม่มีการสื่อสารจริง

ใช้ Jazzy snapshot 5917738c089d353c47885a0f0926fa0de1ee6cf2 (2.0.8-jazzy) สำหรับการทดสอบรุ่นนี้ ดาวน์โหลดซอร์สเป็น ZIP แล้วติดตั้งผ่าน Sketch → Include Library → Add .ZIP Library หรือใช้สคริปต์ติดตั้ง dependency ของ repository

python scripts/install_dependencies.py --config-file arduino-cli.yaml

upstream ระบุ ESP32 core 2.0.2 เป็นบอร์ดที่รองรับ จึงต้องดูผล compile/link ของ core 3.3.10 ในรายงานรุ่นนี้แยกจากการทดสอบ runtime บนบอร์ด การคอมไพล์ผ่านไม่ได้รับรอง Agent discovery หรือ timing บนฮาร์ดแวร์

Serial และ Wi-Fi

#include <RB_Nexus_MicroROS.h>
RBMicroROS.beginSerial(); // USB-UART 115200
// หรือ
bool ok = RBMicroROS.beginWiFi("SSID", "PASSWORD", IPAddress(192,168,1,100), 8888);

บน Serial transport ห้ามพิมพ์ debug ลง Serial เดียวกับ ROS หลังเริ่ม session; beginWiFi() คืน false เมื่อเชื่อมต่อไม่สำเร็จภายใน timeout ไม่รอไม่สิ้นสุด

สถานะและความปลอดภัย

RBMicroROS.updateConnection(agentAlive) รับผล ping จากผู้เรียก ไม่ ping หรือสร้าง node ใหม่เอง ตัวอย่างมอเตอร์ 08/09/15 ใช้ command timeout 500 ms แยกจากสถานะ Agent ส่งคำสั่งซ้ำอย่างน้อย 10 Hz; timeout หยุดมอเตอร์และ PID คำสั่งใหม่จึงเริ่มอีกครั้งได้ เว้นแต่ emergencyStop ยัง latch อยู่

ตัวอย่างเป็น session เดียว ถ้า Agent restart แล้ว session หาย ให้รีสตาร์ตบอร์ด ตัวอย่างหยุดพร้อมไฟกะพริบเมื่อสร้าง entities ไม่สำเร็จ ไม่มีการกล่าวอ้าง reconnect entities อัตโนมัติ
