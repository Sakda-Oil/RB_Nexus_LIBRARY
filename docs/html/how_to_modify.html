3. เริ่มจากสำเนาล่าสุดและสร้าง branch

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์ หากใช้อีกเครื่องให้ clone repository ก่อน เครื่องปัจจุบันมีโปรเจกต์อยู่แล้วจึงไม่ต้อง clone ซ้ำ

# เฉพาะเครื่องใหม่: เปลี่ยนโฟลเดอร์ปลายทางตามที่ต้องการ
git clone https://github.com/Sakda-Oil/RB_Nexus_LIBRARY.git RB_Nexus
Set-Location RB_Nexus
# เครื่องปัจจุบัน
Set-Location 'D:\Desktop\Redbrick\RB_Nexus'
git status --short
# ถ้ามีรายการไฟล์ ให้ตรวจและบันทึกงานเดิมก่อนเปลี่ยน branch
git switch main
git pull --ff-only origin main
git switch -c update/0.2.2

เมื่อ git status ไม่แสดงรายการ หมายถึงไม่มีงานค้าง เลือกชื่อ branch ใหม่หาก update/0.2.2 มีอยู่แล้ว ถ้า pull บอกว่าประวัติ diverged ให้ตรวจประวัติก่อน ห้ามใช้ force push เพื่อแก้โดยเดา

ใช้ตัวแก้ไขข้อความที่บันทึก UTF-8 เช่น VS Code แล้วเปิดโฟลเดอร์ RB_Nexus ทั้งโฟลเดอร์ จะค้นหา API และดูไฟล์ที่แก้ได้ง่าย

4. เตรียมเครื่องมือให้ใช้โค้ดชุดเดียวกัน

เครื่องปัจจุบัน: มี Arduino CLI แบบพกพาและ config อยู่ใน .cache แล้ว กำหนดสองตัวแปรนี้ใน PowerShell ทุกหน้าต่างที่จะใช้คำสั่งต่อไป

$rbCli = (Resolve-Path '.cache/tools/arduino-cli.exe').Path
$rbConfig = (Resolve-Path '.cache/arduino-cli.yaml').Path
& $rbCli version
& $rbCli --config-file $rbConfig core list
python --version

เครื่องใหม่: ติดตั้ง Git และ Python 3 แล้วดาวน์โหลด Windows ZIP ของ Arduino CLI จากผู้พัฒนา แตกไฟล์ให้ได้ .cache/tools/arduino-cli.exe ก่อน .cache ไม่อยู่ใน Git จึงไม่มากับการ clone และ config เดิมมี absolute path จึงไม่ควรคัดลอกข้ามเครื่องโดยไม่แก้ path

# เฉพาะเครื่องใหม่ที่ยังไม่มี config นี้
New-Item -ItemType Directory -Force .cache | Out-Null
$rbCli = (Resolve-Path '.cache/tools/arduino-cli.exe').Path
$rbConfig = Join-Path (Get-Location).Path '.cache/arduino-cli.yaml'
if (-not (Test-Path -LiteralPath $rbConfig)) {
  & $rbCli config init --dest-dir .cache
  & $rbCli --config-file $rbConfig config set directories.data (Join-Path (Get-Location).Path '.cache/arduino/data')
  & $rbCli --config-file $rbConfig config set directories.downloads (Join-Path (Get-Location).Path '.cache/arduino/downloads')
  & $rbCli --config-file $rbConfig config set directories.user (Join-Path (Get-Location).Path '.cache/arduino/user')
}
$rbIndex = 'https://raw.githubusercontent.com/Sakda-Oil/RB_Nexus_LIBRARY/main/package_RB_Nexus_index.json'
& $rbCli --config-file $rbConfig core update-index --additional-urls $rbIndex
& $rbCli --config-file $rbConfig core install RB_Nexus:esp32@0.2.1 --additional-urls $rbIndex
python -X utf8 scripts/install_dependencies.py --cli $rbCli --config-file $rbConfig

เปลี่ยน 0.2.1 เป็นรุ่นที่เผยแพร่แล้วหากเริ่มในอนาคต การติดตั้งนี้ใช้พื้นที่ .cache ของโปรเจกต์ แยกจาก Arduino IDE ปกติ เมื่อ CLI แจ้ง error ให้หยุดแก้ก่อนสั่งขั้นถัดไป ตรวจรหัสออกล่าสุดด้วย $LASTEXITCODE ซึ่งควรเป็น 0

dependency ที่ทดสอบใน 0.2.1 คือ MPU9250 0.4.8, Adafruit BNO08x 1.2.7 และ micro_ros_arduino Jazzy snapshot ที่ระบุใน scripts/install_dependencies.py ส่วน MPU6050 ใช้ register driver ภายใน

5. บทฝึก: เปลี่ยน IMU โดยไม่แก้ไดรเวอร์

เปิด IMURaw.ino ค้นหาบรรทัด RB.imuBegin(RBIMUType::Auto) แล้วเลือกเพียงหนึ่งรูปแบบตามโมดูลที่ต่อ:

RB.imuBegin(RBIMUType::MPU6050, 0x68);
// หรือ
RB.imuBegin(RBIMUType::MPU9250, 0x68);
// หรือ
RB.imuBegin(RBIMUType::BNO085, 0x4A);

หาก AD0 เปลี่ยน address ของ MPU ให้ใช้ 0x69 ส่วน BNO085 อาจเป็น 0x4B ตรวจจากโมดูลจริง เลือก Auto เมื่อต้องการค้นหา BNO085 → MPU9250 → MPU6050 ใช้หนึ่ง IMU ต่อครั้ง

คง Serial.begin(115200), RB.begin() และ RB.update() ไว้ ตรวจ imuDataFresh() ก่อนอ่านค่า อ่าน คู่มือ IMU สำหรับหน่วยและข้อจำกัด MPU6050 ไม่มี magnetometer และรุ่นนี้ไม่ได้ทำ orientation fusion

คู่มือและโค้ดต้องตรงกัน: ถ้าแก้ IMURaw ตัวที่อยู่ใน repository ให้แก้ code block แรกของ README.md และตัวอย่างใน docs/html/imu.html ตามด้วย check_docs.py ตรวจว่า README ตรงกับ sketch ถ้าเป็นการทดลองส่วนตัว ให้ใช้สำเนา sketch แยกจากตัวอย่างหลัก

อีกตัวอย่าง: ปรับมอเตอร์ใน sketch

RB.encoderBegin();
RB.encoderSetPPR(4, 330); // ต้องเป็นจำนวน ticks ที่นับจริงต่อรอบล้อ
RB.motorSetPID(4, 1.2f, 0.5f, 0.05f);
RB.motorSetRPM(4, 60);  // เป้าหมาย 60 RPM
// ใน loop ต้องเรียก RB.update();
// เมื่อต้องการหยุด:
RB.motorStop(4);

ปรับจากเป้าหมายต่ำและทดสอบโดยยกล้อพ้นพื้น motorStop() จะหยุดและปิด PID ส่วน motorSet() เป็น open-loop ช่วง -255..255 และปิด PID ของช่องนั้น

6. ถ้าต้องแก้ไดรเวอร์หรือเพิ่ม API

  1. เขียนพฤติกรรมที่ต้องการก่อน เช่น “อ่าน I2C ไม่ครบต้องไม่ทำเครื่องหมายข้อมูลว่าสด”
  2. ถ้าเพิ่มฟังก์ชันสาธารณะ ให้เพิ่ม declaration ใน RB_Nexus.h และ implementation ใน .cpp ที่เกี่ยวข้อง โดยชื่อ ชนิดข้อมูล และพารามิเตอร์ต้องตรงกัน
  3. ถ้าเพิ่ม IMU ให้เพิ่ม enum, ตรวจ WHO_AM_I/handshake, ตั้งค่า range, แปลงหน่วย และจัดการข้อมูลเก่า/การรีเซ็ต
  4. เพิ่มกรณีทดสอบใน tests/test_imu.cpp หรือ tests/test_driver.cpp ให้ตรวจพฤติกรรมที่เปลี่ยนและเงื่อนไขผิดพลาด
  5. แก้ตัวอย่าง API reference และ release notes ตามผลจริง

สำหรับมอเตอร์ ให้ API หยุดปิด PID ด้วย ส่วน updatePID() ต้องเรียกฟังก์ชันเขียนเอาต์พุตภายในที่ไม่ปิด PID เอง โค้ดปัจจุบันแยก motorStop/motorSet ออกจาก motorOutputStop/motorOutputSet ไว้แล้ว

การเปลี่ยนเซนเซอร์หรือแก้ logic ไม่จำเป็นต้องเปลี่ยน metadata/upstream.json ซึ่งกำหนด ESP32 core/toolchain การอัปเกรด core เป็นงานอีกส่วนและต้องทดสอบ compatibility ใหม่

7. ทดสอบตามขนาดของงาน

7.1 คู่มือและ syntax Python

python -X utf8 scripts/check_docs.py
python -X utf8 -m compileall -q scripts
git diff --check

7.2 Logic โดยไม่ต่อบอร์ด

เครื่องนี้มี Zig แบบพกพาแล้ว ใช้:

python -X utf8 scripts/test_host.py --zig .cache/tools/zig-windows-x86_64-0.13.0/zig.exe

เครื่องใหม่ที่ไม่มี Zig ให้ใช้ g++/clang++ ซึ่งอยู่ใน PATH แล้วสั่ง python scripts/test_host.py หรือใช้ --compiler ระบุไฟล์ compiler; GitHub CI ใช้ g++ บน Linux การทดสอบ fake hardware ตรวจ logic ไม่ยืนยันการทำงานของวงจรจริง

7.3 คอมไพล์เฉพาะตัวอย่างที่แก้

python -X utf8 scripts/compile_examples.py --cli $rbCli --config-file $rbConfig --filter IMURaw
# ตัวอย่าง ROS รวมระบบ
python -X utf8 scripts/compile_examples.py --cli $rbCli --config-file $rbConfig --filter 15_AllSensors

7.4 ก่อนออกรุ่น: ตรวจทุกตัวอย่าง

python -X utf8 scripts/compile_examples.py --cli $rbCli --config-file $rbConfig

รุ่น 0.2.1 มี 39 sketches + GPIO overrides 5 กรณี รวม 44 builds ถ้าเพิ่มตัวอย่างจำนวนอาจมากขึ้น เกณฑ์คือ Failed: 0 และจำนวนที่ค้นพบต้องครบ ชุดเต็มอาจใช้เวลาหลายสิบนาที

ค่าเริ่มต้นของสคริปต์ใช้ --library ชี้ไลบรารีใน checkout จึงตรวจซอร์สที่คุณแก้ หากใช้ --installed-library จะตรวจสำเนาในแพ็กเกจที่ติดตั้งแทน ใช้แบบหลังเมื่อทดสอบแพ็กเกจรุ่นใหม่ที่ build แล้ว

8. อัปโหลดซอร์สที่แก้ลงบอร์ดจริง

ตรวจพอร์ตด้วย board list แล้วแทน COM5 ด้วยพอร์ตจริง คำสั่ง compile ด้านล่างสร้าง binary จาก checkout และ upload จาก build directory เดียวกัน:

& $rbCli --config-file $rbConfig board list
& $rbCli --config-file $rbConfig compile --fqbn RB_Nexus:esp32:rb_nexus --library libraries/RB_Nexus --build-path .cache/manual-imu-build libraries/RB_Nexus/examples/IMURaw
# ทำต่อเมื่อ compile สำเร็จเท่านั้น
& $rbCli --config-file $rbConfig upload --fqbn RB_Nexus:esp32:rb_nexus --port COM5 --input-dir .cache/manual-imu-build
& $rbCli --config-file $rbConfig monitor --port COM5 --config baudrate=115200

ปิด Serial Monitor อื่นก่อนเปิดพอร์ต ใช้ Ctrl+C เพื่อออกจาก monitor ทดสอบวาง IMU นิ่ง หมุนทีละแกน ถอดการเชื่อมต่อ และตรวจ freshness ตัวอย่าง ROS Serial ใช้พอร์ตกับ Agent ห้ามเปิด monitor พร้อมกันหรือพิมพ์ debug แทรกลง transport เดียวกัน

หากใช้ Arduino IDE ปกติ ให้ติดตั้ง dependencies ใน Library Manager ของ IDE ด้วย เพราะ IDE ไม่ใช้ .cache profile นี้อัตโนมัติ หลังออกรุ่นแล้วสามารถอัปเดตผ่าน Boards Manager ได้ตามปกติ

10. บันทึกและส่งงานให้ตรวจบน GitHub

เมื่อเตรียมเลขรุ่นตามหน้าถัดไปแล้ว ให้ดูความเปลี่ยนแปลงก่อน commit อย่าใส่รหัส Wi-Fi จริงหรือข้อมูลลับในตัวอย่างที่จะส่งขึ้น GitHub:

git diff --stat
git diff
git status --short
git add libraries docs scripts tests README.md VERSION
# ถ้าแก้ workflow หรือไฟล์อื่น ให้ add เฉพาะไฟล์นั้นเพิ่มด้วย
git diff --cached --stat
git diff --cached --check
git commit -m "Prepare RB_Nexus 0.2.2: describe the change"
git push -u origin update/0.2.2

เปิด repository บน GitHub → Compare & pull request → เลือก base: main และ compare: update/0.2.2 → อธิบายสิ่งที่เปลี่ยนและผลทดสอบ → Create pull request รอ CI Verification ผ่านก่อน Merge

workflow ปัจจุบันไม่รัน CI เพียงเพราะ push feature branch แต่จะรันเมื่อเปิด/อัปเดต pull request เข้า main และจะเริ่ม Build and release เมื่อ merge เข้า main ดูวิธีตรวจไฟล์ติดตั้งใน ขั้นตอนหลังเผยแพร่

Arduino CLI not foundตรวจ .cache/tools/arduino-cli.exe และกำหนด $rbCli ใหม่ใน PowerShell หน้าต่างนั้น
Python อ่านภาษาไทยไม่ได้ใช้ python -X utf8 และบันทึกไฟล์ UTF-8
missing MPU9250.h / Adafruit_BNO08x.hรัน install_dependencies.py ด้วย --cli และ --config-file ชุดเดียวกับตอน compile
missing micro_ros_arduino.hติดตั้ง Jazzy snapshot ด้วยสคริปต์ dependency; ไม่เพิ่ม dummy types เพื่อหลบ error
คอมไพล์ผ่านแต่เหมือนโค้ดเก่าตรวจ --library ว่าชี้ checkout; อัปโหลด binary ที่เพิ่งสร้าง อย่าเลือก --installed-library ก่อนติดตั้งแพ็กเกจใหม่
check_docs.py บอก README sketch parityคัดลอกตัวอย่าง IMURaw ฉบับเต็มไปใส่ code block C++ แรกใน README ให้ตรงกัน
คำสั่ง upload หา COM ไม่เจอตรวจ board list, สาย USB data, driver CH340 และปิดโปรแกรมที่เปิดพอร์ตค้าง
push rejected / non-fast-forwardgit fetch origin แล้วตรวจ branch/ประวัติ อย่า force push ทับงานใหม่
ต้องการเปรียบเทียบกับรุ่นเก่าใช้ git diff v0.2.1 -- libraries/RB_Nexus/src เพื่อดูความต่าง โดยไม่ลบงานปัจจุบัน

แหล่งอ้างอิง

คู่มือนี้อิงไฟล์ .github/workflows/ci.yml, release.yml และ scripts/ ใน repository ณ รุ่น 0.2.1 หากคุณแก้ workflow ภายหลังให้ทบทวนขั้นตอนด้วย
