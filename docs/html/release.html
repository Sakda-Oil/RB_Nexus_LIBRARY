เปลี่ยนเวอร์ชันและออก Release ใหม่

คู่มือภาษาไทยสำหรับผู้ดูแล RB_Nexus · ปรับปรุง 7 ตุลาคม 2026

อ้างอิงโครงสร้างซอร์สรุ่น 0.2.1 · ใช้ Windows PowerShell · ตัวอย่างรุ่นถัดไป 0.2.2

ตัวอย่าง: เปลี่ยนซอฟต์แวร์ 0.2.1 → 0.2.2 คู่มือนี้อธิบายการทำเอง ยังไม่ได้ออก 0.2.2 ให้ และไม่ต้องเปลี่ยนเวอร์ชันซอฟต์แวร์เพียงเพราะอ่านหรือพิมพ์คู่มือนี้
สารบัญ

เลือกเลขรุ่น · แก้เลข 3 จุด · อัปเดตเอกสาร · สร้างแพ็กเกจ · ทดลองติดตั้ง · เผยแพร่ GitHub · ตรวจหลังเผยแพร่ · แก้เอกสารอย่างเดียว · แก้ Release ล้มเหลว

1. เลือกเลขเวอร์ชันใหม่

ชนิดงานตัวอย่างแนวทาง
แก้บั๊ก ใช้ API เดิม0.2.1 → 0.2.2เพิ่มเลขท้าย
เพิ่มความสามารถ/API โดยยังรักษาวิธีใช้เดิม0.2.1 → 0.3.0เพิ่มเลขกลางและตั้งเลขท้ายเป็น 0
เปลี่ยนวิธีใช้จนโค้ดเก่าต้องแก้เลือกรุ่นใหม่และเขียน migration notesก่อน 1.0 ให้ระบุ breaking changes ชัดเจน; ไม่ถือว่าทุกรุ่น 0.x compatible โดยอัตโนมัติ
แก้คำสะกด/คู่มืออย่างเดียวคง 0.2.1ใช้ขั้นตอนเอกสารล้วนด้านล่าง

ตรวจ Releases ที่มีอยู่ ก่อนเลือกเลข ห้ามนำเลขรุ่นที่เผยแพร่ archive แล้วมาใช้ซ้ำ

เลขซอฟต์แวร์และเลข core คนละเรื่อง: RB_Nexus 0.2.2 ยังใช้ Arduino-ESP32 3.3.10 ได้ ไม่ต้องเปลี่ยน metadata/upstream.json เมื่อแก้ไดรเวอร์ทั่วไป

2. แก้เลขรุ่นหลักให้ตรงกันทั้ง 3 จุด

ทำบน branch งานของคุณหลังเตรียมโค้ดแล้ว:

ไฟล์ที่ 1: VERSION ที่โฟลเดอร์หลัก

0.2.2

ใส่เฉพาะเลข ไม่ใส่ v และไม่ใส่คำอธิบาย

ไฟล์ที่ 2: libraries/RB_Nexus/library.properties

version=0.2.2

แก้เฉพาะบรรทัด version= ส่วน depends เปลี่ยนเมื่อมีเหตุผลและได้ทดสอบ dependency รุ่นใหม่จริง

ไฟล์ที่ 3: libraries/RB_Nexus/src/RB_Nexus.h

namespace RBNexus {
constexpr const char* name = "RB_Nexus";
constexpr const char* version = "0.2.2";
constexpr bool peripheralPinMapAvailable = true;
}

แก้ค่า version ใน namespace เดิม ไม่เพิ่ม namespace ซ้ำ บอร์ดใช้ค่านี้เมื่อรายงานเวอร์ชันไลบรารี

ตรวจเทียบก่อนทำต่อ

Get-Content VERSION
Select-String -Path libraries/RB_Nexus/library.properties -Pattern '^version='
Select-String -Path libraries/RB_Nexus/src/RB_Nexus.h -Pattern 'const char\* version'
git diff -- VERSION libraries/RB_Nexus/library.properties libraries/RB_Nexus/src/RB_Nexus.h

ผลที่ต้องเห็น: ทั้งสามแห่งเป็น 0.2.2 ถ้าต่างกันให้แก้ให้ตรงก่อน build

3. อัปเดตคู่มือและบันทึกการเปลี่ยนแปลง

  • README.md: เลขรุ่นบนหัวเรื่อง วิธีติดตั้ง ตัวอย่าง และลิงก์รายงานใหม่
  • docs/html/*.html: badge รุ่นปัจจุบันและข้อความที่อ้างรุ่นปัจจุบัน; เก็บเลขรุ่นในตัวอย่างเปรียบเทียบ/ประวัติตามจริง
  • docs/RELEASE_NOTES.md: เขียนสรุปปัญหา สิ่งที่แก้ dependency และข้อจำกัด ไฟล์นี้ถูกใช้เป็นข้อความบนหน้า Release
  • สร้าง docs/TEST_RESULTS_0.2.2.md และแก้ลิงก์ “ผลการตรวจสอบรุ่นนี้” ในหน้า HTML ให้ชี้รายงานใหม่ เก็บรายงาน 0.2.1 ไว้เป็นประวัติ
  • ถ้าแก้ CSS/JS และเบราว์เซอร์ยังแสดงของเดิม ให้เปลี่ยน query version ของ style.css/script.js ตามการแก้จริง

อย่า Replace All 0.2.1 เป็น 0.2.2 ทั้ง repository เพราะจะเปลี่ยนประวัติและลิงก์ archive ที่ยังไม่เผยแพร่ ไม่แก้ package_RB_Nexus_index.json ที่โฟลเดอร์หลักด้วยมือ และไม่แก้ checksum ด้วยการคาดเดา

ตัวอย่างข้อความใน RELEASE_NOTES.md

# RB_Nexus 0.2.2

ไม่คัดลอกข้อความ “ผ่านทั้งหมด” จากรุ่นก่อนมาใช้ก่อนรันทดสอบรุ่นใหม่

4. ทดสอบและสร้างแพ็กเกจในเครื่อง

ใช้เครื่องมือและตัวแปรตาม คู่มือเตรียมเครื่อง จากนั้นรันทดสอบใน ขั้นตอนทดสอบ แล้วสร้าง archive:

python -X utf8 scripts/build_package.py --repository Sakda-Oil/RB_Nexus_LIBRARY
python -X utf8 scripts/verify_package.py
python -X utf8 scripts/check_docs.py

build_package.py อ่าน VERSION อัตโนมัติ จึงไม่ต้องแก้ชื่อ ZIP ในสคริปต์เอง ผลที่ควรได้สำหรับตัวอย่างนี้:

dist/RB_Nexus-esp32-0.2.2.zip
dist/package_RB_Nexus_index.json

verify_package.py ตรวจ SHA-256 ขนาดไฟล์ โครงสร้างบอร์ด dependency และซอร์สที่บรรจุใน archive โฟลเดอร์ dist และ .cache ไม่ต้อง commit เพราะ build ใหม่ได้

5. ทดลองติดตั้งแพ็กเกจก่อนเผยแพร่

เปิด PowerShell สองหน้าต่างที่โฟลเดอร์โปรเจกต์ ใช้ config เดียวกันตามคู่มือเตรียมเครื่อง ขั้นตอนนี้ติดตั้งแพ็กเกจทดสอบลง .cache profile และอาจแทนที่บอร์ดรุ่นก่อนใน profile นั้น

หน้าต่าง A: สร้าง test index และเปิดเซิร์ฟเวอร์

python -X utf8 scripts/local_test_index.py --port 8765
python -m http.server 8765 --bind 127.0.0.1 --directory dist

คงหน้าต่างนี้ไว้จนติดตั้งเสร็จ URL นี้รับเฉพาะจากเครื่องตัวเอง ถ้าพอร์ตชนให้เลือกพอร์ตใหม่แล้วเปลี่ยนทั้งสองหน้าต่างให้ตรงกัน

หน้าต่าง B: ติดตั้งและคอมไพล์จากแพ็กเกจ

$rbCli = (Resolve-Path '.cache/tools/arduino-cli.exe').Path
$rbConfig = (Resolve-Path '.cache/arduino-cli.yaml').Path
$rbTestIndex = 'http://127.0.0.1:8765/package_RB_Nexus_test_index.json'
& $rbCli --config-file $rbConfig core update-index --additional-urls $rbTestIndex
& $rbCli --config-file $rbConfig core install RB_Nexus:esp32@0.2.2 --additional-urls $rbTestIndex
python -X utf8 scripts/compile_examples.py --cli $rbCli --config-file $rbConfig --installed-library

ผลสุดท้ายต้อง Failed: 0 จากนั้นกด Ctrl+C ที่หน้าต่าง A อย่าส่ง URL localhost หรือ test index ขึ้นเป็นลิงก์ให้ผู้ใช้ติดตั้ง ถ้าแก้ซอร์สหลังจากขั้นตอนนี้ ต้องสร้าง archive ใหม่และตรวจแพ็กเกจอีกครั้ง

หาก CLI ใช้ archive เก่าจาก cache ขณะพัฒนารุ่นที่ยังไม่เผยแพร่ ให้ตรวจ checksum ใน dist ก่อน และใช้ config/profile ทดสอบใหม่หรือถอนแพ็กเกจทดสอบใน profile นั้นแล้วติดตั้งใหม่ อย่าเขียนทับ asset ที่เผยแพร่แล้ว

6. ส่งขึ้น GitHub และให้ workflow ออกรุ่น

  1. Commit/push branch งาน แล้วเปิด pull request เข้า main ตาม ตัวอย่างคำสั่ง
  2. ตรวจ diff ว่ามีโค้ด คู่มือ VERSION และ release notes ครบ ไม่มี credentials
  3. รอ CI Verification ผ่านใน pull request แล้ว Merge เข้า main
  4. ไปแท็บ Actions รอทั้ง CI Verification และ Build and release สำเร็จ

สำคัญ: workflow รุ่นปัจจุบันเริ่ม Build and release ทุก push เข้า main ยกเว้นการเปลี่ยนเฉพาะ root index ดังนั้นอย่าส่งโค้ดระหว่างพัฒนาหลายครั้งเข้า main โดยไม่เตรียมเลขรุ่นใหม่ และอย่าสร้าง tag/release v0.2.2 เองล่วงหน้า ระบบสร้างให้หลังทดสอบผ่าน

ระบบทำอะไรให้

  1. ทดสอบ logic และลิงก์คู่มือ ติดตั้ง dependency จริง
  2. สร้าง archive ตรวจ checksum และทดลองติดตั้ง
  3. คอมไพล์ทุกตัวอย่าง รวมกรณี flash 8 MB
  4. ตรวจว่า tag เลขรุ่นนี้ยังไม่เคยเผยแพร่
  5. สร้าง Release v0.2.2 และแนบ ZIP + index
  6. อัปเดต package_RB_Nexus_index.json บน main ด้วย commit ของ github-actions[bot]

อย่าอ้างว่าพร้อมติดตั้งเพียงเพราะ git push สำเร็จ ต้องรอขั้น Publish immutable release สำเร็จด้วย

7. ตรวจหลังเผยแพร่และอัปเดตใน Arduino IDE

เปิด Releases → รุ่นใหม่ ตรวจว่ามีไฟล์แนบทั้งสองรายการ:

RB_Nexus-esp32-0.2.2.zip
package_RB_Nexus_index.json

ไฟล์ Source code (zip) ที่ GitHub สร้างให้เองไม่ใช่แพ็กเกจ Boards Manager จากนั้น sync main กลับเครื่อง:

git switch main
git pull --ff-only origin main
Get-Content VERSION
git status --short

เปิด root index ดูว่า version เป็น 0.2.2, URL มี /releases/download/v0.2.2/ และไฟล์ดาวน์โหลดได้ URL ที่ผู้ใช้เพิ่มใน Preferences ยังเป็น URL เดิม:

https://raw.githubusercontent.com/Sakda-Oil/RB_Nexus_LIBRARY/main/package_RB_Nexus_index.json

ใน Arduino IDE เปิด Boards Manager → ค้นหา RB_Nexus → เลือกเวอร์ชันใหม่ → Update/Install; อัปเดต dependency ตาม release notes ถ้ามีการเปลี่ยน แล้ว compile/upload ตัวอย่าง BoardInfo หรือ IMURaw ใหม่

บันทึกผล CI และผลฮาร์ดแวร์จริงลงรายงาน อย่าแก้ archive รุ่นที่เผยแพร่แล้ว ถ้าพบข้อผิดพลาดให้แก้เป็นรุ่นถัดไป เช่น 0.2.3

8. กรณีแก้เฉพาะคู่มือ ไม่ออกรุ่นซอฟต์แวร์

ใช้ขั้นตอนนี้เฉพาะเมื่อไม่มีการเปลี่ยน driver, sketch, scripts, dependency หรือ workflow คง VERSION/library.properties/header ไว้เท่าเดิม และตรวจคู่มือในเครื่องก่อน

git switch main
git pull --ff-only origin main
# แก้เฉพาะคู่มือที่ต้องการ แล้วตรวจ
python -X utf8 scripts/check_docs.py
git diff --check
git add docs/html/how_to_modify.html docs/html/release.html
# เพิ่มชื่อไฟล์เอกสารอื่นเฉพาะที่แก้จริง
git diff --cached
git commit -m "docs: improve maintenance guide [skip ci]"
git push origin main

สำหรับ workflow ปัจจุบัน [skip ci] ข้ามงานที่ trigger จาก push/pull_request จึงไม่พยายามออก Release เลขเดิม ห้ามใช้วิธีนี้กับการแก้โค้ด และถ้า branch protection บังคับ PR/required checks การข้ามอาจทำให้ PR ค้าง Pending — ต้องใช้กระบวนการที่สอดคล้องกับนโยบาย repository และปรับ release trigger ก่อน ห้ามปิดการป้องกันเพื่อหลบการตรวจ

อ้างอิง ข้อจำกัดของ skip instructions จาก GitHub

9. ถ้า Release ไม่สำเร็จ

ปัญหาทำอย่างไร
Release already existsใช้เลขรุ่นใหม่ทั้ง 3 จุด แล้วตรวจ/ออก release ใหม่ ไม่ลบ tag หรือเขียนทับ ZIP เดิม
Compile failedเปิด Actions → job → ขั้นที่ fail → อ่าน compiler error แรก แก้ใน branch แล้วรันตัวอย่างที่เกี่ยวข้องและชุดเต็มใหม่
Download 404ดูว่า asset ถูกอัปโหลดสำเร็จหรือไม่ และ root index ชี้ชื่อไฟล์/รุ่นเดียวกัน ห้ามแก้ URL ให้ชี้ Source code zip
Checksum mismatchอย่าแก้ checksum โดยเดา ตรวจว่ากำลังใช้ archive/index คู่เดียวกัน หาก asset เผยแพร่แล้วให้แก้ผ่านรุ่นใหม่
403 ตอน publish/push indexตรวจ Settings → Actions และสิทธิ์ workflow/token รวมถึง branch protection; ให้ผู้ดูแลปรับเฉพาะสิทธิ์ที่จำเป็น ไม่วาง personal token ในซอร์ส
เครือข่ายล้มเหลวก่อน publishหากยังไม่มี release/tag และซอร์สถูกต้อง ลอง Re-run failed jobs ได้; ถ้ามี asset/release บางส่วนแล้วให้ตรวจสถานะก่อน ไม่ retry ซ้ำโดยเดา
push ถูกปฏิเสธหลัง bot อัปเดต indexดึง main ล่าสุดและรวมงานให้ถูกต้อง ห้าม force push ทับ commit ของ bot
Arduino IDE ยังเห็นรุ่นเดิมรอ index รีเฟรช ตรวจ URL Preferences และ version ใน raw index ก่อนติดตั้งใหม่

10. เช็กลิสต์ก่อนกด Merge

  • เลขรุ่นใหม่ไม่ซ้ำ release เดิม และตรงกันทั้ง 3 จุด
  • ตัวอย่าง/README/HTML ตรงกับ API จริง
  • release notes และรายงานใหม่แยกผลที่ผ่านกับสิ่งที่ยังไม่ทดสอบ
  • ไม่มี Wi-Fi password/token จริงในไฟล์ที่จะ push
  • host tests, docs checks, package verification และ compile ครบผ่าน
  • ทดสอบระบบที่แก้บนฮาร์ดแวร์ตามความจำเป็น
  • ไม่แก้ root index ล่วงหน้า และไม่สร้าง tag ชนกับ workflow
  • หลัง merge รอ workflow สำเร็จ ตรวจ assets และทดลองติดตั้ง
