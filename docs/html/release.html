ขั้นตอนการ Release แพ็กเกจ (Release & Deployment Guide)

กระบวนการปรับเลขเวอร์ชัน การแพ็กไฟล์ zip การอัปเดตไฟล์ดัชนี และการปล่อยขึ้น GitHub Releases

1. การจัดการเลขเวอร์ชัน (Semantic Versioning)

แพ็กเกจ RB_Nexus ใช้มาตรฐาน SemVer (MAJOR.MINOR.PATCH):

  • MAJOR: การเปลี่ยนแปลงสถาปัตยกรรมครั้งใหญ่ หรือมีการ Break API เก่า
  • MINOR: การเพิ่มฟังก์ชันใหม่ รองรับบอร์ด Revision ใหม่ หรือเพิ่มไดรเวอร์เซนเซอร์
  • PATCH: การแก้บั๊ก ปรับปรุงเอกสาร หรือปรับแต่งไทม์มิ่งเล็กน้อย

2. ขั้นตอนการ Release เวอร์ชันใหม่ทีละสเต็ป

  1. ปรับเลขเวอร์ชัน: แก้ไขเลขในไฟล์ VERSION และไฟล์ libraries/RB_Nexus/library.properties ให้ตรงกัน (เช่น 0.2.0)
  2. สร้างแพ็กเกจบอร์ด: รันสคริปต์อัตโนมัติ: 
    python3 scripts/build_package.py --repository Sakda-Oil/RB_Nexus_LIBRARY
python3 scripts/verify_package.py
  3. คัดลอกไฟล์ดัชนีไปยังรูทของ Repository: 
    cp dist/package_RB_Nexus_index.json package_RB_Nexus_index.json
  4. คอมมิตและพุชขึ้น Git: 
    git add .
git commit -m "Release version 0.2.0"
git tag -a v0.2.0 -m "Release version 0.2.0"
git push origin main --tags
  5. สร้าง GitHub Release:

    ไปที่หน้า GitHub Repository เมนู Releases > Draft a new release แนบแท็ก v0.2.0 แล้วอัปโหลดไฟล์ dist/RB_Nexus-esp32-0.2.0.zip ขึ้นเป็น Release Asset

3. การตรวจสอบความถูกต้องก่อน Release (Checklist)

  • [x] ทุกสเก็ตช์ตัวอย่างคอมไพล์ผ่าน 100% ด้วย scripts/compile_all_examples.py
  • [x] ไฟล์ package_RB_Nexus_index.json มีค่า SHA-256 และ size ตรงกับไฟล์ zip ใน dist จริง
  • [x] ผังขาใน RB_Nexus_Pins.h และ pins_arduino.h สอดคล้องกัน
