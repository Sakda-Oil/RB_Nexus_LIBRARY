MPU6050, MPU9250 และ GY-BNO085

RB_Nexus 0.2.1 · ESP32-WROOM-32 · Arduino-ESP32 3.3.10

การต่อ I2C

ขาโมดูลRB_Nexus
SDAGPIO 21
SCLGPIO 22
GNDGND ร่วม
VCC / VINใช้ไฟตามสเปกโมดูลจริง; สัญญาณ I2C และ pull-up ต้องเป็น 3.3 V

ใช้สายสั้นและตั้ง GY-BNO085 ให้อยู่โหมด I2C ตามสกรีน/วงจรของโมดูล โมดูลจากแต่ละผู้ขายอาจมีวงจรจ่ายไฟและ jumper ต่างกัน ไดรเวอร์นี้ใช้ soft reset ผ่าน I2C จึงไม่กำหนดขา INT/RST เพิ่ม

รุ่นAddressสิ่งที่ตรวจ
MPU6050 (6 แกน)0x68 / 0x69WHO_AM_I 0x68; ตรวจการอ่านครบ 14 bytes
MPU9250 + AK89630x68 / 0x69; magnetometer 0x0CWHO_AM_I 0x71 และ AK8963
GY-BNO0850x4A / 0x4BSH2 product handshake และเปิด sensor reports

โหมด Auto เลือก BNO085 ก่อน MPU9250 แล้วจึง MPU6050 หากต่อทั้งสองตัว ระบบใช้หนึ่ง IMU ในแต่ละครั้งผ่าน RB ซึ่ง RB_Nexus เป็นชื่ออ้างอิง object เดียวกัน

RB.imuBegin(RBIMUType::MPU6050, 0x68);
// หรือ
RB.imuBegin(RBIMUType::MPU9250, 0x68);
// หรือ
RB.imuBegin(RBIMUType::BNO085, 0x4A);

ตัวอย่างอ่านค่า

#include <RB_Nexus.h>

void setup() {
  Serial.begin(115200);
  RB.begin();
  // เลือก Auto, MPU6050, MPU9250 หรือ BNO085 (หนึ่งตัวทำงานในแต่ละครั้ง)
  if (!RB.imuBegin(RBIMUType::Auto)) Serial.println("IMU not found");
}
void loop() {
  RB.update();
  static uint32_t last = 0;
  if (millis() - last >= 100) {
    last = millis();
    if (RB.imuDataFresh()) {
      Serial.printf("a[m/s^2] %.3f %.3f %.3f  gyro[rad/s] %.3f %.3f %.3f\n",
        RB.accelX(), RB.accelY(), RB.accelZ(), RB.gyroX(), RB.gyroY(), RB.gyroZ());
    } else Serial.println("Waiting for fresh IMU data");
  }
}

หน่วยและความสดของข้อมูล

  • accelX/Y/Z: m/s² รวมแรงโน้มถ่วง; ขณะวางนิ่งขนาดเวกเตอร์ควรประมาณ 9.81
  • gyroX/Y/Z: rad/s; magX/Y/Z: µT
  • roll/pitch/yaw: องศา; quaternionW/X/Y/Z: ค่าจาก sensor fusion
  • เรียก RB.update() บ่อย ๆ หรือ imuUpdate() เพื่ออ่านข้อมูลใหม่
  • imuDataFresh(500) ตรวจทั้ง accel และ gyro; imuOrientationFresh(500) ตรวจ orientation แยกต่างหาก
  • isIMUAvailable() หมายถึงเริ่มต้นสำเร็จ ไม่ใช่การยืนยันว่าข้อมูลล่าสุดยังสด ค่า getter เป็นค่าที่ cache ไว้ จึงต้องตรวจ freshness ก่อนใช้

MPU6050: 6 แกน

ใช้ไดรเวอร์ register ภายใน ไม่ต้องติดตั้ง Adafruit MPU6050 เพิ่ม ตั้งช่วง ±4g / ±500 deg/s, sample rate 200 Hz และอ่านเฉพาะเมื่อ data-ready ข้อมูลแปลงเป็น m/s² และ rad/s เช่นเดียวกับสองรุ่นอื่น

MPU6050 ไม่มี magnetometer และรุ่นนี้ไม่ทำ orientation fusion ให้เซนเซอร์นี้: mag, Euler และ quaternion คืน NaN; imuOrientationFresh() คืน false ใช้ accel/gyro กับ ROS raw IMU ได้ หรือเพิ่มตัวกรอง fusion บน ROS ตามงานจริง ไม่สามารถให้ yaw อ้างทิศเหนือจาก MPU6050 เพียงตัวเดียว

MPU6050 และ MPU9250 ใช้ address ชุดเดียวกัน หากต่อพร้อมกันต้องตั้ง AD0 ให้ต่างกัน และ API นี้เลือกใช้หนึ่งตัวต่อครั้ง

การสอบเทียบและแกน

MPU9250 ใช้ Madgwick ของ hideakitai และค่า factory trim ของ AK8963; ตั้ง magnetic declination เป็น 0 (ทิศเหนือแม่เหล็ก) ยังต้องสอบเทียบ bias/scale ตามโมดูลและการติดตั้งจริงก่อนใช้ควบคุมทิศทาง BNO085 ใช้ SH2 Rotation Vector และ calibration ภายในชิป

Euler/quaternion เป็นกรอบอ้างอิงของไดรเวอร์แต่ละรุ่น โดย MPU9250 ใช้ convention ของไลบรารี hideakitai ไม่ควรสลับรุ่นแล้วสมมติว่าแกน fusion เหมือนกัน Topic ROS ตัวอย่างจึงส่ง raw acceleration/gyro และตั้ง orientation_covariance[0] = -1; หากต้องการ orientation ใน ROS ENU ต้องแปลงแกนและการติดตั้งให้ถูกต้องก่อน

หากอ่านไม่ได้

ตรวจ address, ไฟเลี้ยง, I2C mode, pull-up และกราวด์ ลองบัส 100 kHz ด้วย RB.begin(100000) เมื่อพบการสื่อสารไม่เสถียร ต้องยืนยัน BNO085 I2C กับโมดูลจริงบน ESP32 ของคุณ หากข้อมูลหยุดไหลจะไม่ส่งค่าค้างออก ROS และต้องแก้การต่อสาย/เริ่ม IMU ใหม่
